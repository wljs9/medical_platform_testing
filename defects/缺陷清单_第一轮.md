## DEF-001 【P1】创建患者/医生接口 gender 枚举取值与数据库契约不一致

- **模块**:患者 / 医生 创建接口
- **接口**:`POST /api/patients`、`POST /api/doctors`
- **复现步骤**:
  1. 调用 `POST /api/patients`，body 传 `{"gender":"男","name":"张三",...}`
  2. 观察到 HTTP 500
- **期望结果**:接口接收并正确入库(或对非枚举值返回明确的 400 + 取值范围提示)
- **实际结果**:返回 500，数据库 `gender enum('M','F')` 只接受 M/F，接口无任何枚举校验
- **根因分析**:数据库字段类型为 `enum('M','F')`，接口层无参数校验直接透传；接口文档/测试数据使用的是中文"男/女"，导致合法的业务语义(中文)与存储格式(M/F)不一致，报错不可控
- **证据**:`SHOW COLUMNS FROM patient` → `gender enum('M','F')`
- **状态**:待开发/已确认

## DEF-002 【P1】患者身份证字段长度不足：`id_card char(10)` 存不下 18 位身份证号

- **模块**:患者模块
- **接口**:`POST /api/patients`、`PUT /api/patients/{id}`
- **复现步骤**:
  1. 调用 `PUT /api/patients/2`，body 传 `{"idCard":"110101199005011234"}`(18 位)
  2. 观察到 HTTP 500
- **期望结果**:正常保存 18 位身份证号
- **实际结果**:返回 500，错误为 `Data too long for column 'id_card'`
- **根因分析**:表结构 `id_card char(10)`，仅能存储 10 位字符；身份证标准为 18 位。**数据建模与业务域不匹配**，导致正常业务数据无法落库
- **证据**:`SHOW COLUMNS FROM patient`、接口返回 `e.getMessage()` 中的 SQL 错误
- **状态**:待开发/已确认

## DEF-003 【P1】更新患者接口主键处理存在覆盖风险，可能更新到错误记录

- **模块**:患者模块
- **接口**:`PUT /api/patients/{id}`
- **复现步骤**:
  1. `PUT /api/patients/5`，body 传 `{"name":"张三","patientId":1,...}`
  2. 观察实际更新的记录
  3. 测试发现：body 中传 `patientId` 时，更新行为异常，成功提示与实际更新目标不一致(达到 id=1 的记录)
- **期望结果**:无论 body 是否携带 patientId，都只更新路径中指定的 `{id}` 记录
- **实际结果**:`controller` 中 `patient.setPatientId(id)` 强制用路径 id 覆盖 body 中的 patientId，但 MyBatis `WHERE patient_id = #{patientId}` 存在参数为 null/被覆盖导致更新错行或更新 0 行的风险，且接口仍返回"更新成功"
- **根因分析**:`PatientController.updatePatient()` 使用 `setPatientId(id)` 覆盖 body 主键，HTTP 路径参数与 body 实体主键两套赋值逻辑并存，缺少"body 禁止携带主键字段"的约束，存在更新错记录的数据风险
- **状态**:待复测确认细节后转开发

## DEF-004 【P1】删除患者功能不可用：未级联删除子表记录，触发外键约束

- **模块**:患者模块
- **接口**:`DELETE /api/patients/{id}`
- **复现步骤**:
  1. 选择一条**已有病历/检查申请**的患者，如 `DELETE /api/patients/1`
  2. 观察到 HTTP 500，错误含外键关联
- **期望结果**:删除患者时级联删除其病历、检查申请，或给出明确的业务提示
- **实际结果**:返回 500，因 `medical_record`、`examination_request` 两表均有外键指向 `patient`，删除被外键约束拦截
- **根因分析**:`PatientService.deletePatientWithRecords()` 中，级联删除子表的 `deleteByPatientId` 两行代码**被注释掉**，仅执行患者删除 → 违反外键完整性。**功能设计(级联删除)未真正实现**
- **证据**:`PatientService.java` 65-72 行注释
- **状态**:待开发/已确认

## DEF-005 【P2】科室创建接口无参数校验：空名称可成功入库

- **模块**:科室模块
- **接口**:`POST /api/departments`
- **复现步骤**:
  1. `POST /api/departments`，body 传 `{"departmentName":""}`
  2. 观察到 HTTP 200 且数据库中插入空名称记录
- **期望结果**:拒绝空名称，返回 400 或业务提示
- **实际结果**:成功入库(200)
- **根因分析**:接口层无 `@NotBlank` 等参数校验、无手写判空逻辑
- **状态**:待开发/已确认

## DEF-006 【P2】科室名称无唯一性约束：重复科室可入库

- **模块**:科室模块
- **接口**:`POST /api/departments`
- **复现步骤**:
  1. `POST /api/departments`，body 传 `{"departmentName":"内科"}`
  2. 重复执行，观察到数据库存在多条"内科"
- **期望结果**:业务上科室名称应唯一，重复创建应被拒绝
- **实际结果**:可重复插入
- **根因分析**:表结构缺少唯一索引，接口层无重名校验
- **状态**:待开发/已确认

## DEF-007 【P3】查询不存在的资源 ID 返回 200 而非 404

- **模块**:所有资源查询接口(科室/医生/患者/病历/检查申请)
- **接口**:`GET /api/departments/99999999` 等
- **复现步骤**:
  1. `GET /api/departments/99999999`
  2. 观察到 HTTP 200，响应体为空/null
- **期望结果**:按 REST 语义返回 404
- **实际结果**:返回 200 空结果
- **根因分析**:Mapper 查询到 null 后直接返回，Controller 未对不存在资源做 404 处理
- **状态**:待开发/已确认

## DEF-008 【P2】接口异常响应泄露完整 Java 堆栈信息(安全/规范性)

- **模块**:所有接口(异常走 catch 分支返回 `status(500)` 的)
- **复现步骤**:
  1. `POST /api/patients` 传非法 body(如超长 idCard / 中文 gender)
  2. 观察响应体
- **期望结果**:返回格式化的错误码 + 友好错误信息，不暴露内部堆栈
- **实际结果**:响应体原样返回 `e.getMessage()` 甚至完整 `trace` 堆栈(SQL 异常、Java 类名、行号)
- **根因分析**:Controller 统一 `catch (Exception e) { return status(500).body("失败: "+e.getMessage()) }`，错误信息未脱敏。可能泄露表结构、SQL 语句、代码包结构，安全风险
- **状态**:待开发/已确认
